# 细节说明

设备身份、登录会话、传输层、请求模式、风控原理、设置项与排障。安装与快速上手见 [README](../README.md)。

## 登录（需要你在浏览器里完成一次）

1. 在手机或电脑浏览器打开 https://chat.deepseek.com 并登录（人机验证由你完成）。
2. 取 `localStorage.userToken`：
   - 电脑：F12 → Console → `JSON.parse(localStorage.userToken).value` → 复制结果
   - 手机：地址栏输入 `javascript:prompt('token',JSON.parse(localStorage.userToken).value)`（需手动敲入，粘贴会被浏览器去掉 `javascript:` 前缀）
3. 打开 DSH 设置 →「DeepSeek 网页版」→ 粘贴 token → 「校验并保存」。

也可以命令行：

```bash
dsh-deepseek-web login --token <userToken> --label 工作号
dsh-deepseek-web doctor
```

> 邮箱验证码登录在无浏览器环境下通常被人机验证拦住，设置界面里保留入口但多为兜底用。

## 账号与风控

- 每个账号的请求串行；两次请求之间的间隔**在随机区间里取**（默认 2500~4500ms，设置页可调），失败会退避。
- 三层节奏闸门：随机间隔 → **滚动窗口限速**（默认 30 分钟最多 20 次）→ **长任务长休**（连续 15 轮后歇 60~180 秒；距上次请求超过 10 分钟才算「人歇过了」，计数才清零）。
- **人类节律（默认开）**：再叠一层「像人」的行为 —— ①间隔按本轮**消息字数**加打字时间（3.4 字/秒 + 发送前停顿，45 秒封顶：真人不会 2000 字一秒打完）；②按本地作息放大深夜间隔（01:00~06:30 系数再乘 2.6，凌晨三点持续活跃是最刺眼的机器特征）；③每轮 5% 概率插入 8~75 秒**走神停顿**；④每账号 **24 小时滑动窗口条数上限**（默认 240，超了直接停住报错，**不换号硬闯** —— 换号恰好最像「多开小号轮换」）。四项都可在「运行设置」里关。
- 429 → 该账号冷却 60s 起指数退避（上限 10min）并切下一个账号。
- 401 → 若该账号保存了密码，先自动重新登录并把新 token 换到原账号（同一账号原地续跑，不打断对话）；没存密码或重登失败才标记「登录失效」。
- 指定账号：模型名写 `deepseek-chat@工作号` 即可固定到某个账号。
- **默认不自动换号**：某个号失效/被限流时直接报错停下（旧的自动轮换在「高级选项（高危）」里，默认关）。

### 反代痕迹审计：做到哪一步才「不像转发的」

把「像人」拆成可以逐条核对的面，比笼统说「防封」有用。下表是当前实现状态，附证据来源。

| 层 | 真实浏览器 | 本插件现状 | 结论 |
|---|---|---|---|
| TLS ClientHello（JA4/JA3、扩展顺序） | Chrome 131 | native 档 = curl_cffi `chrome131`，实测 JA4 `t13d1516h2_8daaf6152771_02713d6af862` | 一致 |
| HTTP/2 帧（SETTINGS/WINDOW_UPDATE/伪头顺序） | Chrome | curl_cffi 复刻，实测 h2 指纹 `52d84b11…` 与 Chrome 同 | 一致 |
| 请求头集合 | 含 `sec-ch-ua`/`sec-fetch-*`/`accept-language` | `humanHeaders()` 补齐，版本与 UA、impersonate 同源 | 一致 |
| **出站栈是否唯一** | 只有一个栈 | v1.0.62 前：对话 h2 + 体检/登录 h1.1 混用 → 现在统一 | 已修 |
| 设备身份 | `x-device-id` 稳定 | 登录页/引擎共用同一 UUID | 一致 |
| Cookie | 页面自己的 jar | 登录时抓的 cookie 原样回放 | 接近，但不会像页面那样滚动更新 |
| 是谁在发包 | 人开着浏览器 | v1.0.63 起可切「手机浏览器」档：直接接管手机上那台真 Chrome 的调试端口 | 可选，默认关 |
| 账号前几条消息 | 先打招呼再谈正事 | 登录后先闲聊 1~2 句（可关） | 已做 |
| 消息的形状 | 人打出来的话 | v1.0.65 起提示词是「我：/你：」对话体，长输出截断，不再出现 API JSON 外壳 | 已做 |
| 节奏（间隔/打字/作息/走神/每日上限） | 人的节奏 | 人类节律默认开；打字间隔自 v1.0.64 起为对数正态逐字模型 | 已做 |
| 设备关联 | 一台设备一套身份 | 「清除设备痕迹」换新 UUID / 清指纹 / 清计数 | 可选；治设备关联，不治账号历史 |
| 会话复用 | 同一条对话 | 复用 `chat_session_id` 续聊 | 一致 |
| `accept-encoding` | `gzip, deflate, br, zstd` | 由底层库决定（Node 只发 gzip/deflate） | **残留**：为不让解压失败打断对话，没有强行伪造 |
| 对话内容 | 人写的自然语言 | 系统契约 + 工具 schema + 多轮工具循环 | **最大残留**，见下 |

**最大的痕迹不在网络，在内容。** 服务端看到的是一段段结构化的工具调用循环（截图里那些 `|| DSML || invoke name="bash"`），
加上每次请求前面那段固定的系统契约。这属于「用聊天界面当 API」的性质判断，不是指纹问题 ——
任何 TLS/头部/节奏技巧都改不了它。想让工具链长期跑，正路是官方 API（`api.deepseek.com`）；网页版这条路适合人的量级。

## 被禁言了怎么办（以及为什么会到这一步）

站点的处置分两档：`50006` **禁言**（还能登录、不能发消息，有到期时间）和 `40012` **封号**（更重）。到期前插件不会再用这个账号发任何请求，账号行会显示到期时间和站点原文。

必须说清的现实：**用网页版承载「工具调用密集的 agent 循环」本身就是站点禁止的自动化访问**。设置页里能看到 DSH 一轮轮把 `bash` 之类的工具调用塞进网页对话 —— 这在服务端看是「用聊天界面当 API」，比频率更接近「违反使用规范」的判据。指纹、节律、每日上限能降低被统计识别的概率，**改不了一条自动化访问链路的性质**。

真要长期跑工具链，正路是官方 API（`api.deepseek.com`，按量付费、明确允许程序化调用）；网页版这条线适合「人在网页里聊」量的使用。被禁言后：① 到期前别再用这个号；② 需要继续用时换官方 API 的 provider，而不是开小号轮换（多号轮换会把处置扩散到关联账号）。

## 多设备与设备身份（为什么会被踢下线）

站点把「设备」当成登录态的一部分：请求头 `x-device-id`、登录页的 `localStorage["deepseek-device-id:chat"]`，账号安全里还有「登录设备管理」。同一个账号如果不断以「新设备」登录（比如每次换浏览器窗口、WebView 清了存储、或者 node 引擎请求不带设备头），就很容易被判定异常登录 —— 表现就是刚登好没多久又被踢回登录页。

插件现在把三处身份统一成**同一个 UUID v4**（`state/device.json`，权限 0600，首次生成后不再变）：

| 位置 | 以前 | 现在 |
|---|---|---|
| 密码登录请求体 | `device_id` = 32 位 hex（站点不认，视为 `INVALID_DEVICE_INFO`） | 同一个 UUID v4 |
| 内嵌/浏览器登录页 | 站点前端自己随机生成，每次可能都是新设备 | 代理在 `<head>` 里预置同一个 UUID，并给 fetch/XHR 补 `x-device-id`、`x-device-model: ""` |
| 引擎 HTTP 请求 | 完全不带设备头 | `baseHeaders()` 统一带 `x-device-id` / `x-device-model` |

另外：同一账号并发的 401 触发重登时会**合并成一次**（以前会同时发起好几次登录，站点上就多出几次会话）。

**升级后第一次**：`device.json` 里的旧 hex 会被迁移成 UUID，站点可能把这次当成「新设备登录」要求一次邮箱验证码 —— 在内嵌/浏览器登录页里输一次即可，之后设备就固定下来了。如果账号安全里的设备列表很乱，去 `chat.deepseek.com` → 设置 → 账号安全 → 登录设备，把不认识/旧的设备删掉。

**还想更稳的话**：手机和插件用**不同账号**（插件本来就支持多账号池），这样两边互不干扰；同一账号不要同时开着网页版和插件长时间跑。

## 传输层：默认走真实浏览器（Node 直连是高级选项）

网页端判断「这是不是脚本」不只看频率，也看**网络栈**。Node 的 undici 在 TLS 层就露馅：

| | JA4 | cipher 列表哈希 | ALPN |
|---|---|---|---|
| Node fetch（undici） | `t13d5212h1_…` | — | **h1** |
| Chrome / Edge | `t13d1516h2_…` | 一致 | h2 |

这几项**调参修不了**（参考实现的实测表格也是这个结论）。所以 v1.0.56 起把对话请求交给**本机真实浏览器**，v1.0.57 起改成三档：

| 模式 | 请求由谁发出 | PoW 在哪解 | 需要什么 |
|---|---|---|---|
| `auto`（默认） | **browser → native → node** 依次尝试，选到第一个可用的 | 对应层 | 见下 |
| `browser`（强制） | 本机 Chrome / Edge 的真实页面（CDP，页面真的登录着） | 页面里用官方 wasm | 能跑的浏览器；起不来就报错，绝不静默降级 |
| `native`（本地伪装，v1.0.58 新增） | **curl_cffi**（BoringSSL impersonate `chrome131`）：TLS/JA4、HTTP/2 帧都同 Chrome，纯 CPU | 官方 wasm 本地算（payload 与服务端期望一致） | python3；缺依赖时自动装 `curl_cffi` 到状态目录（不动系统 Python） |
| `node`（高级选项，高危） | Node 直连（旧实现） | Node 里 `WebAssembly.instantiate` | 无 |

**为什么要 native 这一层**：「所有手机」这个前提判了 Chromium 的死刑 —— 手机容器里它起不来（本机实测 `SIGTRAP`）。而浏览器指纹并不需要浏览器，只需要一条配置正确的 TLS 连接：

| 客户端 | JA4 | HTTP/2 (Akamai) | 结论 |
|---|---|---|---|
| Node fetch（`node` 档） | `t13d5212h1_b262b3658495_8e6e362c5eac` | 无（**HTTP/1.1**） | 一眼脚本 |
| **curl_cffi `chrome131`（`native` 档）** | **`t13d1516h2_8daaf6152771_02713d6af862`** | `52d84b11737d980aef856699f885ca86`（Chrome） | 与浏览器一致 |
| Chrome（参考实现实测表格） | `t13d1516h2_…` | 同 Chrome | 目标基线 |

依赖是**按需自动装**的：先看系统 Python 有没有 `curl_cffi`；没有就 `pip install --target <状态目录>/native-libs`；连 pip 都没有就自建 venv 跑 `get-pip.py` 再装（Ubuntu 精简 rootfs 也能装成）。装不上时 `auto` 会继续回退 Node 并亮红字，并把原因写清楚。想手填解释器路径用 `nativePython`（等价 `DSW_PYTHON`），想走国内镜像用 `DSW_PIP_INDEX`。

- **v1.0.57 的检测不再只看「文件在不在」**：候选范围覆盖 `PATH`、`/opt/google/chrome`、`/usr/lib/chromium*`、snap、flatpak，以及 **Playwright（`~/.cache/ms-playwright`）/ Puppeteer（`~/.cache/puppeteer`）缓存**（很多机器的 `/usr/bin/chromium` 只是软链到这些缓存）。设置页会显示**找到的路径 + 版本 + 能不能启动**，还能手填浏览器路径（`browserPath`，等价 `DSW_BROWSER_PATH`）。
- 检测分两级：① 冒烟启动（`--dump-dom about:blank`）；② 真的起 BrowserTransport 连 CDP 开页面。**起不来必须报真实原因**（信号 / 退出码 / 最后几行日志），不能只说一句「检测不到」。
- 「起不来」很多是**运行环境限制**而不是配置错误：例如 Android 手机容器里 Chromium 会在开页面时 `SIGTRAP`（`/dev/shm` 不可用、`/proc/sys/fs/inotify/*` 被 mask）。这种环境下 `auto` 会回退 Node 直连并明确告诉你风险；想「宁可报错也不回退」就选 `browser`。
- 换号/换 token 时会把登录态重装进页面（cookie + `localStorage.userToken`），否则会出现「页面是登录页、请求却带合法 Authorization」这种真人身上不会有的组合。
- 回滚：设置页切 `Node 直连（高危）`，或环境变量 `DS_NETWORK_TRANSPORT=node`（改完立即生效，不用降级版本）；想强制「必须浏览器」用 `DS_NETWORK_TRANSPORT=browser`。
- 传输层只影响**对话请求与 PoW**；列会话、体检这类只读管理请求仍走 Node。
- 浏览器传输跑在无头模式；要过人机验证时用 `DSW_BROWSER_HEADED=1` 起可见窗口（同一个 profile，验证完把窗口关掉）。

**自动换号默认关闭**（旧的「一被限流就换号」收进高级选项）：几分钟内换号继续发是极强的机器行为特征，多号交替活跃反而更容易被判成「同一人的多开小号」，处置可能波及全部关联账号。

## 防风控：连「发给 AI 的内容」一起管

站点拦的不只是频率，还有**请求的形状**。参考实现（`cv-superding/dsh-deepseek-web-login`）实测出来的几条，这里能照做的已经照做：

| 特征 | 以前 | 现在 |
|---|---|---|
| 两次请求的间隔 | 固定值 × 抖动系数（方差很小） | **区间内随机**：默认 2500~4500ms，保险模式 5000~8000ms |
| 连续发几十轮 | 阈值 10 轮、歇 25~70 秒，「隔两分钟再来一波」就洗掉了计数 | 阈值 **15 轮**、歇 **60~180 秒**，且「距上次请求 >10 分钟」才算人歇过 |
| 短时间高频 | 10 分钟 16 次 | **30 分钟 20 次**（保险模式 12 次） |
| 技能目录（每轮都发） | 每条带完整描述，45 条约 11k 字符 | **只发名字 + 一句「用 skill 工具加载」**（省 90%+） |
| 工具描述 | 逐字照发（单个工具可到 2000+ 字符） | 上限 **220 字**；参数里只压说明文字，属性名/类型/必填一个不少 |
| 站点安全分类块 | 会以 `<ds_safety>…</ds_safety>Safe` 混进正文 | 发送前/收流时剥掉（成对、未闭合、半截残片都处理） |

为什么这些也算防风控：每轮请求**体量**和**密度**同样是判定依据。首屏从 ~25k 字符压到 ~3k（只算本插件负责的那部分）后，同样的对话在服务端看来「像个人在网页里聊」得多。

三个回滚开关（都是环境变量，改成旧行为不用降级版本）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `DSW_WEB_COMPACT_TOOLS` | 开 | `0` = 工具描述/参数说明逐字照发（旧行为） |
| `DSW_WEB_STRIP_SKILLS` | `names` | `off` = 技能目录原样保留；`all` = 整块删掉 |
| `DSW_WEB_TOOL_DESC_CHARS` | 220 | 单个工具描述保留多少字符 |

> 说实话的部分：这些只**降低**被识别成自动化的概率，**不构成「不会被封」的保证**。逆向网页端本身违反站点条款，风险是「判罚多严」而不是「会不会被抓到」。要稳定就别用网页版账号，走官方 API。

## 请求模式（原始 / 保险）

设置页「运行设置」里的 **请求模式** 决定两件事：**发给网页模型的提示词长什么样**、**请求有多急**。

两者的提示词确实不一样：

| | 原始模式 `raw`（默认） | 保险模式 `safe` |
|---|---|---|
| 提示词开头 | 你自己发的 system 消息（原样） | 先插入一段「【使用规范】不输出违法违规/暴力/仇恨/攻击性内容，遇到就礼貌拒绝……」，再接你的 system 消息 |
| 工具清单 | 完整 schema + 完整描述（约 1200 字/工具） | 描述压缩到 200 字，参数仍在（`compact`） |
| 末尾约定 | 一行回复格式约定 | 同样的约定 + 「输出前先自检是否符合使用规范」 |
| 历史预算 | 约 118k tokens | 约 48k tokens（更早的历史会被裁掉） |
| 发送节奏 | 按配置的随机区间（默认 2500~4500ms） | 至少 5 秒、区间更宽（5000~8000ms）；窗口次数再压到 ~60%；同账号并发强制 1 |

原始模式：最接近真人在网页里提问，模型发挥完整，适合日常写代码、翻译、总结。
保险模式：多一层内容护栏 + 更保守的流量特征，适合把插件当无人值守服务跑、或账号已经被警告/禁言过的情况；代价是长对话更早开始遗忘、工具描述变短（复杂工具偶尔会漏参数）。

两种模式下，被禁言/封号的账号都会被账号池跳过。

## 界面：四个页签，一次只看一页

设置页顶部是一条吸顶的**页面切换条**，把 7 张卡按用途分成 4 页（参考 `dsh-deepseek-web-login` 的分页做法）：

| 页签 | 包含 | 用来做什么 |
|---|---|---|
| **账号** | 账号管理、添加账号 | 平时待得最多的一页：看当前账号、登录状态、加号/换号 |
| **登录** | 登录会话、登录状态 | 掉登录时排查：cookie 罐、登录页回传、PoW/代理自检 |
| **用量** | 网页版用量、调用台账 | 看今天跑了多少 token、间隔与失败分类 |
| **运行** | 运行设置（引擎）、页面设置、维护 | 调参、改卡片顺序、检查更新与重置 |

- 当前页记在本机（`localStorage`），刷新不会跳回第一页；`?` 提示、「结果条」在所有页都可见。
- 「页面设置」里的上下移只影响**同一页内**的卡片顺序，跨页顺序由上面的页签固定，**不参与**切号、会话复用与凭证。

### 精简后的账号卡

每个账号默认只有一行主操作：**检查 · 登录 · 设为当前 · 更多**。

- 「登录」= 存了密码就走内嵌窗口自动填表；没存密码但掉登录了就走登录页，登录成功后 token 原地回填。
- 「更多」展开后才出现：改名、重新登录、内嵌登录、浏览器登录、复制账号密码、改密码、禁用、`↑` `↓`、导出、恢复上次登录、退出并登录其它、删除。**功能一个没删**，只是默认不占地方。
- 账号卡标题右侧同理：默认 **新建分组 · 全部体检 · 更多**，「更多」里是导出备份 / 导入备份 / 查重复 / 多选。
- 「添加账号」顶部多了**登录方式切换条**：内嵌窗口 / 系统浏览器 / 粘贴 token / 邮箱密码 —— 一次只展开一种，界面不再堆成一面墙。

## 登录会话与账号管理

**登录会话（cookie 罐）**：每次登录浏览器都会拿到一个本机会话 id，服务端 cookie 存在 `jar-<sid>.json`。设置页的「登录会话」卡把它们列出来：属于哪个账号、多少个 cookie、什么时候登的、token 回传过几次。站点还没掉登录时点「用这次会话登录」——重开同一个会话，页面把 token 直接抓回来，**不用密码、不用验证码**；确认没用的会话可以「清理」（只删 cookie 罐，账号不动）。

**恢复上次登录**：账号卡上出现「恢复上次登录」按钮（仅当这个账号记录过登录会话），语义与上面一致，但会顺手把 token 原地回填到那个账号，不会多出一个重复账号。

**重复账号检测与合并**：同一个 DeepSeek 账号（`user_id` 相同或完整邮箱相同）在账号库里登了两次是常事（先内嵌登一次、又用浏览器登一次）。「查重复」按 `user_id` / 完整邮箱分组，每组只留一个（优先「存了密码 + 采集过指纹 + 最近用过」），其余账号的 cookie、密码、分组先并到保留者身上再删除。面板会就地提示「发现 N 组重复账号」，点「一键合并」收口。

**批量与排序**：点「多选」勾选账号，可一次启用 / 禁用 / 移组 / 删除；每个账号左右两侧的 `↑` `↓` 调整列表顺序（`order` 字段持久化，只影响面板显示顺序，不动调度与凭证）；「导出」只导这一个账号的 JSON（含 token/cookie，不含密码）。删除账号会一并清掉它保存的密码、登录会话关联，并把「当前账号」指针清空（不会留下指向幽灵账号的配置）。

## 设置项

| 字段 | 默认 | 说明 |
|---|---|---|
| autoStart | true | 选择/调用网页版模型时自动拉起引擎 |
| idleStopMs | 600000 | 空闲多少毫秒后关停引擎 |
| sendGapMs / sendGapMaxMs | 2500 / 4500 | 同一账号两次请求的间隔区间（毫秒），每次在这段区间里随机取 |
| rateWindowMs / rateMaxInWindow | 1800000 / 20 | 滚动窗口限速：这段时间内最多发这么多次，超了就长休（0 = 关闭，不建议） |
| maxConcurrency | 4 | 全局并发上限（账号池总和） |
| embedLogin | true | 在设置页里内嵌登录窗口（实验）；关掉即回到「新标签页/系统浏览器打开登录页」的旧行为，也就是内嵌方案的回滚开关 |
| saveLoginCredential | true | 登录成功时把登录表单里的邮箱+密码加密保存在本机（下次自动填表 / token 失效自动重登）；关掉则不保存 |
| autoRelogin | true | token 失效时用保存的账号密码自动重新登录 |
| requestMode | raw | 请求模式：`raw` 原始（提示词原样）/ `safe` 保险（插使用规范 + 更慢更保守） |
| transport | auto | 传输层：`auto` 真实浏览器 → 本地伪装（curl_cffi）→ Node 直连 / `browser` 只许真实浏览器 / `native` 本地伪装 / `node` 直连（高级选项，高危） |
| humanRhythm | true | 人类节律：打字时间 + 作息曲线 + 走神停顿（关掉只保留纯随机间隔） |
| dailyMsgs | 240 | 每账号 24 小时滑动窗口发送上限，超了停住报错；0 = 不限 |
| nightQuiet | true | 01:00~06:30 自动把间隔放大（真人要睡觉） |
| autoSwitch | false | 账号失效/被限流时是否自动换下一个号（**默认关**；开了就是旧行为，机器特征明显） |
| sectionOrder | usage,ledger,engine,accounts,addAccount,sessions,diagnostics | 设置页卡片顺序，由最下方「页面设置」的 ↑/↓ 调整 |

设置页的卡片分进四个页签（账号 / 登录 / 用量 / 运行），每页内从上到下默认是：**账号** 账号管理 → 添加账号；**登录** 登录会话 → 登录状态；**用量** 网页版用量 → 调用台账；**运行** 运行设置 → 页面设置 → 维护，另有引擎日志卡。（没有账号时「添加账号」临时置顶，默认页也是账号页。）
「页面设置」（默认收起）可以调整前五块的先后顺序（自动保存，可「恢复默认顺序」）。

最底部是「关于」卡片：作者 irerc · DeepSeek Harness，显示插件名与版本。

最下方独立的「维护」卡片提供两个操作：

- **清空 Token 用量记录**：删除 `state/usage.json`，插件内累计用量归零（不影响账号、会话、登录状态）。
- **重置所有插件设置**：把 config 恢复默认值（自动启动、空闲休眠、发送间隔、并发、卡片顺序），会先弹出确认窗口再执行；窗口里可选勾选「同时删除已登录账号和 token（不可恢复）」，不勾选则保留账号。
  - 确认窗口内还有二级页「删除所有账号和数据」：彻底清空账号/token/cookie、用量统计、cookie 罐与全部设置（`POST /factory-reset`），需再点一次「确认彻底删除」。

## 内嵌登录窗口（实验）与回滚

站点风控会拦掉「插件内直接把账号密码 POST 给站点」的登录，但**真实网页里的登录能过**。内嵌窗口就是把真实登录页搬进设置页，省掉切浏览器这一步：

- 原理：本机 18090 端口有一个登录反向代理，把 `chat.deepseek.com` 的登录页镜像成一个本机独立 origin（`127.0.0.1:18090`），设置页用 iframe 显示它；cookie 只写在本机，DSH 页面本身不接触站点 cookie。
- 成功后：登录页里的注入脚本把 token 回传给插件（`/dsh-deepseek-web/login/token`），同时 `postMessage` 告诉设置页 —— 设置页自动关掉窗口并刷新账号列表。
- **自动填表 / 自动保存账号密码**：登录页的注入脚本会从登录表单和站点自己的登录请求里拿到你输入的邮箱和密码，随 token 一起回传；插件把它**加密存在本机**并挂到这个账号上（「运行设置 → 登录时自动保存账号密码到本机」可关）。下次点这个账号的「内嵌登录」，账号密码会自动填好并提交；只存了完整邮箱的账号，会先自动填好邮箱，密码输一次之后也就保存下来了。
- 账号行：默认只显示「检查 / 登录 / 设为当前 / 更多」；「更多」里保留「内嵌登录」（自动填好账号密码）、「浏览器登录」（新标签页/系统浏览器，旧方式）、复制账号密码、改密码、排序、导出、删除等全部操作。添加账号卡片顶部先选登录方式（内嵌窗口 / 系统浏览器 / 粘贴 token / 邮箱密码），内嵌窗口白屏或被站点风控挡住时切到「系统浏览器」。
- 苹果账号：Apple 授权页禁止被任何网页内嵌，所以 **Apple 登录只能走外部窗口**，这条线路标为实验、优先级低。
- 前置条件：浏览器和 DSH 在同一台机器上（代理只监听 `127.0.0.1`）。

**回滚**（三选一，都不用重装旧包）：

1. 设置页「运行设置」→ 取消勾选「在设置页里内嵌登录窗口（实验）」→ 立即回到 v1.0.41 的行为（登录页走新标签页/系统浏览器），iframe 不再出现；
2. 环境变量 `DS_EMBED_LOGIN=0` 启动 DSH，效果同上（配置文件里的开关也会被写成关）；
3. 代码级回滚：`git revert` 本版本提交，或直接重装 v1.0.41 的压缩包（账号数据在 `~/.dsh/storages/dsh-deepseek-web`，不受影响）。

系统浏览器线路（`POST /dsh-deepseek-web/login/browser` → 宿主 `openOnDevice`）**完整保留**，内嵌开关关不关都能用。

## 排障

- 模型调用报「没有可用账号」→ 设置里没登录或 token 全部失效。
- 报 502 `AUTH_REQUIRED` → token 过期，重新粘贴。
- 引擎起不来 → 看设置页「引擎日志」或 `state/engine.log`。
- 端口冲突：入口固定 `127.0.0.1:18081`，引擎内部用 `18082`。

## 风险提示

直连网页接口属于自动化访问，可能触发站点风控；多账号会放大风险。插件做了串行、节流、真实浏览器请求头与自然提示词，但**不能保证不被限流或封禁**。
